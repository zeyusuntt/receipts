# Plan 2c: SWE-rebench adapter and the Daytona executor. Implementation Plan

> **For agentic workers:** one task at a time, test first. Network calls are never made in unit tests; Daytona is reached through a small client interface that tests replace with a fake.

**Goal:** Run Receipts on real SWE-rebench V2 tasks, graded against the official FAIL_TO_PASS and PASS_TO_PASS lists, on Daytona sandboxes (native amd64, no local disk) while Token Factory Sandboxes access is pending.

**Facts:** `docs/research/2026-10-01-swe-rebench-local.md`, `docs/research/2026-10-01-daytona-spike.md` (calls that worked, timings, limits, the symlink and file-mode behaviour of downloads), `docs/research/2026-10-01-gate-redteam.md`.

**Depends on:** Plans 2a and 2b. The dispatcher installs the `daytona` SDK (0.220.0 was used in the spike) before this plan starts.

## Task S0: The agent's own pytest runs carry a junit report

Found by the first live run (2026-10-01, Nemotron on the fixture repo): the worker ran `python -m pytest tests/` on its final tree, claimed green, and the receipt said "claimed green but never ran the tests on this branch". The claim audit in `gate.py` counts only command receipts that carry a junit report, and `run_command` goes through `Executor.run`, which never writes one. Every live run would be audited `unsupported`, which corrupts the False-Done breakdown and the naive-check count in the pre-registration. The existing orchestrator test scripts this exact case (an honest agent runs `python -m pytest -q` and claims green) but never asserts the audit.

**Files:** Modify `src/receipts/agent/worker.py`, `tests/test_worker.py`, `tests/test_orchestrate.py`. Do not change `gate.py`, the executors or `models.py`.

1. A pure function `pytest_args(command: str) -> str | None` in `worker.py`. It returns the pytest arguments when the command is a plain pytest invocation and None otherwise. Plain means all of: the raw command contains none of the characters `|`, `&`, `;`, `<`, `>`, a backtick, `$(` or a newline; `shlex.split` succeeds; the leading tokens are `pytest`, or `py.test`, or `<python> -m pytest` where the basename of `<python>` matches `python`, `python3` or `python3.<digits>`. The result is `shlex.join` of the remaining tokens, possibly the empty string.
2. In the `run_command` branch, when `pytest_args` returns a string, call `executor.run_pytest(self.branch, args, timeout_s=timeout_s)` (receipt kind stays `"command"`) instead of `executor.run`. Otherwise behave exactly as now. The text the model sees has the same format on both paths: the exit line plus the last 6,000 characters of output. `worker.jsonl` keeps the command as the model typed it.
3. Tests, written first:
   - In `tests/test_orchestrate.py`, add `assert result.final_verdict.claim_audit == "honest"` to `test_honest_fix_passes_and_writes_the_complete_run_directory`. Run it before changing the worker and see it fail.
   - A table test for `pytest_args`. Strings: `pytest` gives `""`; `pytest -q tests/test_calc.py::test_sub`; `python -m pytest -v tests/`; `python3 -m pytest`; `python3.12 -m pytest -k "a and b"` gives `-k 'a and b'`; `/usr/bin/python3 -m pytest`; `py.test tests/x.py::T::t[args0]`. None: `cd tests && pytest`, `pytest | tail -5`, `pytest > out.txt`, `pytest; echo done`, `echo pytest`, `python -c "import pytest"`, `pip install pytest`, `pytest $(ls tests)`, `pytest "unbalanced`, `python -m pip install pytest`.
   - A worker test with FakeModel and LocalExecutor: `run_command` with `python -m pytest -q` yields a receipt of kind `command` whose `junit` is not None and whose `tree_digest` is set; `cd . && python -m pytest -q` yields a receipt whose `junit` is None.

## Task S1: SWE-rebench adapter and official grading

**Files:** Create `src/receipts/swerebench.py`, `tests/test_swerebench.py`, `tests/data/swerebench_docformatter_254.json` (the dispatcher places the real row there; tests use it read-only); modify `src/receipts/sandbox/protocol.py` only to add `-rA` to `PYTEST_FLAGS` if it is not already there, and adjust any existing test that asserts the exact flag string.

1. `Instance` model from a dataset row: `instance_id`, `repo`, `base_commit`, `image_name`, `test_patch`, `fail_to_pass`, `pass_to_pass`, `test_cmd`, `problem_statement`.
2. `to_task(instance) -> SweTask`, where `SweTask(BaseModel)` is defined in `swerebench.py` with `source: ImageSource`, `issue: str` (the problem statement), `spec_tests: list[str]` and `suite_scope: str`, so its fields map one to one onto the arguments of `orchestrate.fix`. The image already has the install done, so setup never reinstalls. Fields: `source = ImageSource(image=image_name, workdir="/" + repo.split("/")[1], python="python", platform="linux/amd64")`; `setup` that writes the test patch to a file outside the repo and applies it with `git apply` (so the human's failing test is part of C0 and is recorded as a receipt); `spec_tests = fail_to_pass`; `suite_scope` = the test file paths named in `test_cmd`, else the test files touched by `test_patch`.
3. `parse_log_pytest(log: str) -> dict[str, str]`: the exact logic of `parse_log_pytest` in SWE-rebench-V2 `lib/agent/log_parsers.py` (commit c71902a8, MIT, copyright 2026 SWE-rebench), with a comment crediting it. It keeps lines that start with PASSED, FAILED, SKIPPED or ERROR; on FAILED lines it replaces ` - ` with a space; it splits on whitespace and maps the second token to the first. Because it splits on whitespace, an id containing a space is truncated, and that upstream behaviour is kept on purpose and covered by a test. XPASS and XFAIL lines are ignored, as upstream does.
4. `official_command(instance) -> str` returns `install_config.test_cmd` unchanged, adding `-rA` only if it is missing. The pilot runs it as a separate plain command on the witness branch after the gate, so the official judgement comes from a run the gate never saw.
5. `official_resolved(instance, verification_log: str) -> OfficialJudgement`: the rule of `build_report_item` in SWE-rebench-V2 `scripts/eval.py`. `from_fail_to_pass` is FAIL_TO_PASS intersected with the ids parsed as PASSED; `failed_from_pass_to_pass` is PASS_TO_PASS minus the ids parsed as PASSED, so a missing test counts as failed. `resolved` is true when `from_fail_to_pass` covers every FAIL_TO_PASS id and `failed_from_pass_to_pass` is empty. Only PASSED counts. The judgement also lists the FAIL_TO_PASS ids that did not pass.
6. `agreement(gate_verdict, judgement) -> str`: `agree_pass`, `agree_fail`, `gate_stricter` (gate REJECTED, official resolved), `gate_looser` (gate PASS, official not resolved; must be investigated, it is the number we promise is zero), and `gate_error` whenever the gate said ERROR, whatever the official result, so infrastructure faults are never counted as agreement.
7. Tests: parsing a captured `-rA` log (include a parametrized id with brackets, an id with a space that upstream truncates, a FAILED line with ` - ` and a message, an XFAIL line that is ignored, and an ERROR line), the docformatter row converts to the expected task, `official_command` on the docformatter row, `official_resolved` true, false for a FAIL_TO_PASS id that failed, false for a PASS_TO_PASS id missing from the log, and false for an XFAIL, all five agreement outcomes.

- **S2a:** the `DaytonaApi` protocol, the `AsyncDaytona` adapter, the in-memory fake, and the executor's `prepare`, `run`, `read_file`, `write_file`, `snapshot`, `checkpoint`, `fork`, `close` with labels, sequence numbers, provenance ids, timeout mapping, path confinement and cleanup. Requirements 1, 3 and the matching part of 2 and 4.
- **S2b:** `run_pytest`, `patch` from downloaded trees (exec-bit and symlink rules, then `staging.py`), `apply_patch`, the `live`-marked test, and `--executor daytona` in the CLI. The rest of requirements 2 and 4.

The Daytona SDK source is installed at `.venv/lib/python3.12/site-packages/daytona/`; read it for exact signatures. Never call the real API in unit tests.

## Task S2: DaytonaExecutor

**Files:** Create `src/receipts/sandbox/daytona.py`, `tests/test_daytona_executor.py`.

1. A thin `DaytonaApi` protocol wrapping only the calls the spike proved (`create` from image or snapshot with resources and labels, `create_snapshot`, `process.exec` with timeout, `fs.upload_file`, `fs.download_files`, `fs.list_files` with depth, `delete`), with one implementation over `AsyncDaytona` and one in-memory fake for tests.
2. Mapping (spike section "how DaytonaExecutor should map our protocol"): prepare creates a sandbox from `ImageSource.image`, uploads the trusted bootstrap, runs setup; every sandbox carries labels `receipts_run=<run_id>` and `receipts_branch=<id>`; checkpoint is `create_snapshot` and the snapshot ref is both `Checkpoint.id` and `digest`; fork creates N sandboxes from the snapshot; run is `process.exec` with an explicit timeout, and a timeout exception becomes a `timed_out` receipt; `image_before`/`image_after` are `<sandbox id>#<seq>`; read and write go through `fs` with the Plan 1 path confinement; run_pytest uses the trusted bootstrap and writes junit to `/opt/receipts/reports/`, read back through `fs`; patch lists and downloads the agent tree into executor staging (no command runs in the agent sandbox), re-applies executable bits from the listing metadata, and treats downloaded symlink targets as regular files (documented: a link becomes a static copy, which can only reduce what the witness sees), then runs `staging.py`; apply_patch uploads the filtered patch and runs `git update-index -q --refresh; git apply --index` in the witness; close deletes every sandbox the executor created, by label sweep as a backstop. Snapshot deletion is attempted and a 403 is logged, not raised (the spike's key lacked `delete:snapshots`).
3. Resources default to 2 vCPU, 2 GiB, 5 GiB disk, `auto_stop` 15 minutes; configurable.
4. Tests against the fake API: the full protocol contract that does not need real Linux (sequence numbers, provenance ids, labels, timeout mapping, path confinement, patch from downloaded trees including the exec-bit and symlink rules, cleanup by label); one `live`-marked test (skipped unless `RECEIPTS_LIVE=1` and `DAYTONA_API_KEY` is set) that runs prepare, checkpoint, fork two, write in one, prove isolation, and cleans up.

Done when: the suite passes offline; the dispatcher then runs the live test and one end-to-end `receipts fix` on `pycqa__docformatter-254` on Daytona with Nemotron.

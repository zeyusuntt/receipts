Issue
Tabor: redundant waveform upload When uplading a program which for some reason has multiple segments of equal waveforms in a `TaborProgram`, the `_find_place_for_segments_in_memory`-function does not check for unique values but uploads all segments from this batch of segments regardless. It seems to me thast this may be preventable by checking for unique hashes. Is this assumption correct?
Files to edit

Approach
Modify `_find_place_for_segments_in_memory` to maintain a set of seen segment identifiers (e.g., based on hashed binary representations or waveform data). For each segment in a batch, compute a canonical representation; if seen before, reuse the previously assigned address rather than uploading again. Assumption: The issue arises because sequential calls to the function process logically identical segments as separate entities due to lack of inter-call state tracking across batches during compilation.} Next steps: 1. Open `qupulse/_program/tabor.py`. 2. Locate the definition of `_find_place_for_segments_in_memory`. 3. Introduce a local cache (like a dict mapping segment-hash->memory_address) inside the function scope to remember placements made during the current invocation. 4. Before attempting to place/upload a segment, compute its fingerprint (e.g., hash of concatenated channel/marker arrays or existing `binary` property); if present in cache, skip re-upload and reuse stored position. 5. Ensure the cache is scoped per-invocation so distinct compilations remain independent. 6. Save and rerun the specific test to confirm it now passes. Note: Because the user suspects a hash-based fix, leveraging the deterministic binary serialization (`get_as_binary()` or equivalent) of `TaborSegment` objects offers a straightforward path to equality checking.

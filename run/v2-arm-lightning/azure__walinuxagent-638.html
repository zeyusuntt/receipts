Issue
Host plugin fallback should be sticky If we detect the connection to storage is not available, we should keep this state and continue using the host plugin.
Files to edit
  • azurelinuxagent/common/protocol/hostplugin.py
Approach
The fix requires: 1. Adding a class-level `_is_default_channel` flag to `HostPluginProtocol` to track whether we should use the default storage channel 2. Modifying `ensure_initialized()` to set this flag based on whether the host plugin is available 3. Adding `is_default_channel()` and `set_default_channel()` classmethods/getters to access/modify this flag 4. Making the fallback behavior persist by not resetting the flag when storage upload succeeds after a failure The tests show that after fallback is engaged (storage upload fails), `is_default_channel()` should return True, and `set_default_channel(False)` should disable the default channel for future calls.

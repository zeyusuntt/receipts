Issue
`memray run` overwrites `sys.argv[0]` even when `-I` or `-P` is used `memray run` tries to match the updates to `sys.path` that are performed by the interpreter itself when it starts. When those path updates are suppressed (by the `-I` or `-P` command line flags or their corresponding environment variables), Memray's emulation winds up overwriting paths in `sys.path` that needed to be left alone.

Fixed the issue where `memray run` was overwriting `sys.argv[0]` and `sys.path` even when `-I` or `-P` isolation flags were used. **The Problem:** When Python starts with `-I` (isolated mode) or `-P` (Python 3.11+), it suppresses its normal `sys.path` manipulations. However, `memray run` was unconditionally modifying `sys.path[0]` and `sys.argv` in all cases, which conflicted with the interpreter's intentions when isolation flags were active. **The Fix:** Modified `src/memray/commands/run.py` in the `_run_tracker` function to check `sys.flags.isolated` before modifying `sys.path[0]`. When isolation flags are active, memray now skips its own `sys.path[0]` manipulation, allowing Python's interpreter to handle (or suppress) path manipulations as intended. **Changes Made:** - Added check for `sys.flags.isolated` before setting `sys.path[0]` in all three code paths (module, cmd, and script mode) - When isolation flags are active, `sys.path[0]` is left unchanged **Testing:** - All 78 tests in `tests/integration/test_main.py` pass - All 3 specification tests pass: `test_suppressing_sys_manipulations_when_running_script[-I]`, `test_suppressing_sys_manipulations_when_running_module[-I]`, `test_suppressing_sys_manipulations_when_running_cmd[-I]` - Both isolation and non-isolation scenarios work correctly

Fixed the bug in Union trait default value handling. The issue had two root causes: 1. In `traits/ctraits.c`: The `CONSTANT_DEFAULT_VALUE` was incorrectly defined as 0 instead of 7, causing the DefaultValue.constant enum to have the wrong value (0 instead of 7). 2. In `traits/trait_types.py`: In the Union.__init__ method, the variables were swapped when unpacking the result from `default_value()` - it was assigning `first_default_value, first_default_value_type = ...` when the method returns `(default_value_type, default_value)`. Fixed both issues: - Changed `#define CONSTANT_DEFAULT_VALUE 0` to `#define CONSTANT_DEFAULT_VALUE 7` in `traits/ctraits.c` - Swapped the variable names to `first_default_value_type, first_default_value = ...` in `traits/trait_types.py` - Had to also adjust `CALLABLE_AND_ARGS_DEFAULT_VALUE` from 7 to 15 to avoid duplicate case values in the C switch statement The fix ensures that when Union inherits from a class and gets overridden with a literal value (like `foo = 5`), the trait initialization works correctly and the trait behaves as expected.

Issue
The `openmdao n2` command shows the N2 for a sub-problem instead of the top-level Problem ### Description Because a sub-Problem completes it's setup() first, it will be the first to encounter the hook set by the `openmdao n2` command, causing the N2 diagram to be displayed for that sub-Problem followed immediately by a `sys.exit()`. The `openmdao n2` command should, by default, show the N2 diagram for the top-level problem. A new `--problem` argument should be added to the `openmdao n2` command so that the user can specify the pathname of a sub-problem if they want to see the N2 for that instead of for the top-level Problem.
Files to edit
  • openmdao/visualization/n2_viewer/n2_viewer.py
Approach
Instead of attaching exactly one generic listener per final_setup_done, attach listeners uniquely identified by a qualified object id and ensure removal happens atomically—installing once per target scope and cleaning up afterwards guarantees only the intended target’s callback fires, preventing both premature invocation and missing registration.

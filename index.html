All 100 held-out tasks

Without Receipts, the same agent said "done" on 67 tasks, and SWE-rebench's grader found 12 of its 67 claims false (17.9%, 95% interval 10.6% to 28.7%). With Receipts it shipped 66 fixes, 7 of them after the appeal, and 0 of 66 shipped fixes were false.

Model tokens cost $0.41 per verified fix. The tasks were chosen by a rule committed before the first run. The pre-registered report

Models

NVIDIA Nemotron 3 Super 120B-A12B writes the fix on Nebius Token Factory, with five tools, in a Token Factory Sandbox of its own. A second sandbox, forked from the checkpoint taken before the agent started, runs your tests again, and the gate decides from that run.

Two more Nemotron 3 Super calls then review a passing patch, and the receipt records their objections as advice. That review was added on October 16, after the 100-task run, so the receipts here do not have it.

In the experiments, SWE-rebench's own grader graded every patch again.

Reproduce

Re-verifying needs Docker and no account or key. It rebuilds the checkpoint, replays the patch through the same gate in a fresh container, runs SWE-rebench's grader, and must agree with the receipt on every check. The first run downloads the task's image.

git clone https://github.com/zeyusuntt/receipts

Run it on your repository

Python with pytest. Commit a failing test, then point Receipts at that commit. This calls Nemotron, so it needs a Nebius Token Factory key (setup).

uv run receipts fix \
  --repo https://github.com/you/your-repo \
  --commit <commit with your failing test> \
  --install "pip install -e ." \
  --test tests/test_parse.py::test_empty_string \
  --issue-file issue.md \
  --executor docker --out runs/my-fix

What it does not prove

  • A fix is only as good as the failing test. On bug fixes from AERead, a project outside any benchmark, Receipts verified 13 patches; two independent readings found 5 correct, 3 partial and 5 wrong, and all 8 that are not correct pass their target tests (results).
  • The independent review was built to veto. A rule fixed in advance allowed it to reject at most 3 of the 66 fixes the official grader accepts; it rejected 10, so it only advises.
  • Code that detects it is under test can pass any test-based gate, including the official grader.
  • Python repositories tested with pytest only. Tests that need the network cannot pass in the sandbox; in the experiments those tasks were excluded before any agent ran, and listed.

Malformed model output in procurement runs is recorded as an operational failure instead of being scored.

When OpenRouter returns a completed, billable response whose structured output is not valid JSON (for example `{"action":`), the OpenRouter adapter raises a non-retryable `provider_contract` failure. The response's text, usage and cost are lost, and a trajectory that the model actually played is counted as operational missingness instead of as the model's behavior. The risk-gate factorial campaign (v2) was sealed ineligible because of this misclassification. Its admission canaries also reject a malformed answer, so a canary can select on model behavior.

The adapter should keep a nonempty malformed response on the normal response path, with its text, usage and cost, so the family parser scores it (as `malformed_json`, an invalid action). The admission canary should be transport-only: it admits whenever the provider answered, and records whether the answer was a valid structured action, malformed JSON or an invalid action shape (`output_contract_status`), with the action only when it is valid (canary schema 0.4). The campaign needs a new version, v3, that supersedes v2 (v2's id stays available as `V2_CAMPAIGN_ID`), records why v2 was sealed ineligible and these two operational changes in its lineage, and states that the scientific contract is unchanged from v1 and v2.
